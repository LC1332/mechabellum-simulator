## 0. 结论先行

本轮不应继续按“哪个兵种胜率偏高就调低伤害”的方式修补。review、用户新增规则和现有证据共同指向四类更底层的误差：

1. 爬虫缺少可信的占位、拥挤、绕行和近战接敌模型，导致大量爬虫可能重叠、错误同时开火，或把单位推成不真实的位置；
2. 兵种的表面攻击力、武器周期、弹数、转向和换靶共同决定 120 秒实际输出，当前引擎对多类重炮和特殊武器的实际输出明显失真；
3. 猎犬燃烧弹、鬼鳐全弹发射/高爆弹药、狂蝎双发、台风残骸引爆等科技混合了“单体 DPS”和“清杂效率”两种不同问题，不能共用一个伤害倍率修正。
4. transition 当前没有“每方每回合最多主动解锁 1 个单位”的计数门，也没有把兵种专家和特定增援统一转换为不消耗额度的自动解锁。

因此本轮主线固定为：

```text
新 .grbr 与游戏代码/数据表
  -> oracle 场景身份与轮次对齐
  -> 逐帧移动/索敌/转向/攻击/伤害遥测
  -> 单体 120s DPS 与清杂曲线双基准
  -> 爬虫占位/拥挤/绕行原语
  -> 重炮转向与逐兵种武器周期修正
  -> 纯 DPS 科技与清杂科技分包实现
  -> 主动解锁额度 + 专家/增援自动解锁
  -> 八库 + 新 oracle 库 + 1106 局 paired A/B
  -> engine freeze 后再通知 RL/Transformer 重建 sim labels
```

本轮的第一目标是让过程量对 oracle 更准，而不是保证总 winner 准确率单调上升。任何默认规则必须先有 oracle 证据；观察性胜率表只用于安排实验优先级，不能直接决定数值。

| `s29c` | 112/150 = 74.7% | 旧爬虫推挤库是回归参考，不足以单独裁决新模型 |
| `chaff_xsep=1` 旧 A/B | `s29c +4`、`s28 +7`、`s26 -8` | 简单删除跨类型碰撞不是可直接烘焙的最终答案 |

当前实现中还有三个与本轮直接相关的事实：

- `_surface_matrix` 主要以圆半径计算表面距离，无法表达大型地面单位的矩形边界和四周可用接敌面；
- `_separate` 是软分离代理，已有 `chaff_xsep/chaff_nosep/sep_tan` 等实验开关，但没有“前排占位—后排绕行—空位补入”的完整语义；
- 引擎已有 `facing`/`attack_angle`/`rotate_speed` 支路，但默认 `facing=False`，所以重炮转向时间通常没有进入实际输出。

### 1.3 回放轮次对齐风险

初步检查发现，`units_fight` 部署快照与 `match.reports` 中的战后单位集合不能靠相同 round 数字直接假定一一对应。清杂回放中相邻轮次的待测兵种会发生错位；如果不先回连 `unit index/mech/card/report`，很容易把台风的结果记到火神或把下一轮科技带入上一轮。

因此本轮 T0 必须生成显式的 `oracle_case_id` 与对齐表：

```text
source replay hash
source round / fight round / report round
side
unit index + mech id + card identity
level / techs / buffs / equipment / tower skills
start position + heading
opponent target identity
fight result row
```

无法唯一回连的记录标为 `ambiguous`，不得进入数值拟合。

### 1.4 review 给出的爬虫规则边界

本轮将以下内容视为用户冻结的方向性规则，并用 oracle 定量：

- 爬虫寻路接近目标后攻击；
- 剑齿虎这类大型单位可先近似为矩形/正方形障碍，不能被爬虫穿入；
- 爬虫真实近战射程约为 10，最近一层可贴近至表面距离约 0；
- 剑齿虎内圈大约同时容纳 20 只爬虫，后续爬虫形成外圈而不是叠在同一点；
- 正面无空位时，后排会沿目标侧面绕向背面；
- 全部围满后，群体会表现出沿目标周向流动/转圈；
- 已经在射程内并攻击的爬虫保持目标；仍在移动且目标不在射程时，可以因更近目标出现而换靶；
- 爬虫之间的推挤必须保留，否则清杂武器会因单位堆叠而一次命中过多目标。

上述是机制约束，不等于指定某种算法。可以使用局部避障、势场、周界槽位或混合近似，但必须通过同一组轨迹 Gate。

## 2. 目标、成功标准与非目标

### 2.1 必做目标

- 把两份新 `.grbr` 转成版本化、可回连、不可错轮的 oracle case manifest；
- 在 Windows oracle 环境采集逐帧位置、朝向、目标、攻击状态、伤害与死亡事件；
- 建立单体 120 秒输出与清杂效率两套独立 benchmark；
- 为大型地面目标引入可审计的矩形/方形 footprint 距离与不可穿越约束；
- 实现爬虫之间的有限体积、内外圈拥挤、侧向绕行、空位补入和射程外换靶；
- 让爬虫在剑齿虎周围的同时开火数、接敌时间和空间密度接近 oracle；
- 对胜率高估 TOP 兵种重新测量 120 秒实际输出，并分离基础武器、转向、换靶和弹道误差；
- 对明显低估兵种做同样复核，禁止只向下修高估兵种；
- 实现/修正猎犬燃烧弹、鬼鳐全弹发射/高爆弹药、狂蝎双发、台风残骸引爆；
- 用升级骇客对维修剑齿虎做 120 秒阈值实验；
- 实现每方每回合主动 `UnlockUnit` 最多成功 1 次；
- 实现兵种专家、单位获得卡及经 oracle 确认的单位专属增援自动解锁对应 mech，且不消耗主动解锁额度；
- 完成新 oracle 微型场景、八库、人类回放三层 paired A/B，并冻结证据和默认开关。

### 2.2 成功分层

| 层级 | 通过条件 |
|---|---|
| 数据可信 | 8 个有效新 replay pair 全部完成 fight/report 身份对齐；所有数值可回连原回放与 oracle build |
| 动力学可信 | 大型目标不可穿透；内圈活动爬虫约 20；后排形成外圈并能绕至空闲侧；无大规模坐标重叠 |
| 单体输出可信 | 选定兵种的 120 秒实际伤害/攻击次数/首发时刻在预设容差内，击杀靶场景使用 TTK/截断曲线 |

### 2.3 明确非目标

- 不修改 `pysim/rl/**`、`tests/rl/**` 或 Transformer/RL 训练、cache、arena 代码；
- 不在本轮继续扩展装备 ID；装备 runtime 只做受新伤害/移动管线影响的回归验证；
- 不用观察性胜率差直接修改兵种基础伤害、生命或射程；
- 不一次性把所有地面单位改为高成本刚体物理引擎；
- 不为了复刻一张截图写死“剑齿虎只能站 20 只”的兵种特判；
- 不把所有近战单位自动套用爬虫的群体流动模型；第一阶段只覆盖爬虫，复用需另有 oracle；
- 不实现 2v2、特殊地图或部署阶段碰撞；除本轮明确新增的解锁额度/自动解锁外，不扩展其他经济规则；
- 不处理堡垒防空弹幕的对空标定；review 已明确它不适合维修剑齿虎对地方法；
- 不在 oracle 未采集时把 provisional 参数烘焙为默认。

开工时创建 `crawler-damage-oracle-v1` manifest，记录：

- 原始 `.grbr` hash、case id、地图、seed、tick/帧率、坐标系；

- 所有用户冻结规则、静态反向结论和仍未确认的字段。

原始遥测与归一化摘要分开保存。不得把账号、token、用户名或隐私绝对路径写入可提交产物。

### 3.2 证据优先级

1. 游戏代码/数据表：确认武器弹数、attack duration、turn speed、footprint、效果类和字段应用顺序；
2. 同机逐帧注入遥测：确认运行时状态、边界时序、实际伤害和动态寻路；
3. 新 `.grbr`：确认用户构造场景在真实游戏中的最终表现；
4. PySim 微型场景：确认实现公式与边界；
5. 1106 局观察性统计：确认覆盖和集成影响，不作为真实规则来源。

静态表与运行时冲突时，以可复现运行时为准并记录冲突。单次视觉观察只能产生假设，不能直接升级 confidence。

### 3.3 Oracle 遥测契约

每帧或固定 tick 至少输出：

```text
t / frame / seed
unit_id / member_id / card_id / side / mech / level
position / heading / velocity / footprint
hp / max_hp / active_heal / active_buffs
current_target / movement_target / target_distance_surface
attack_state / cooldown / prepare_progress / turn_remaining
fire_event(weapon, volley, projectile_count, target, t)
impact_event(projectile, point, victim_ids, t)
damage_event(source, victim, raw, actual, overkill, tags)
retarget_event(old, new, reason)
collision_or_avoidance_event(neighbor, overlap, correction)
death_event(killer, victim, t)
winner / end_time / FightReport fields
```

爬虫场景额外派生：

```text
inner_ring_count(t)
in_attack_range_count(t)
simultaneous_attackers(t)
min/median/p90 neighbor distance(t)
front/side/back occupancy(t)
target switches per crawler
first_contact / first_fire / 50%-engaged timestamps
unique splash victims per impact
```

### 3.4 复跑规则

- 确定性场景固定 seed 至少复跑 3 次，逐帧 digest 必须一致；
- 存在弹着点/选靶随机性的场景至少 20 seeds，报告均值、标准差、分位数；
- control/treatment 必须只差一个待测变量；
- 一个场景含多个待测兵种时，只有在 FightReport/事件能够逐 source 归因时才可分别出数；否则拆成单兵种重跑；
- 配置变更必须新建 run family，不覆盖第一次结果。

### T11：每回合解锁额度与自动解锁

#### T11.1 规则定义

用户冻结规则：

```text
每个玩家每个回合最多成功执行 1 次主动 UnlockUnit。

兵种专家自动解锁对应兵种；
拿到明确对应某兵种的特定增援时，也自动解锁对应兵种。

自动解锁不消耗本回合的 1 次主动解锁额度。
```

主动额度按玩家、按回合独立计算。只有“将一个原本 locked 的 mech 变成 unlocked”的成功主动动作才消耗额度：查询已解锁单位、失败动作、资金不足和被 Undo 撤销的动作均不得永久占用额度。解锁价格为 0 的主动解锁仍然消耗额度，因为限制的是次数而不是花费。

#### T11.2 单一规则源与状态

在 `pysim/transition/rules.py` 增加：

```python
BASE_MANUAL_UNLOCK_LIMIT = 1

UnlockLimitQuote(
    base=1,
    used=player.manual_unlocks_this_round,
    remaining=max(0, base - used),
)
```

- [ ] `PlayerState` 增加 `manual_unlocks_this_round: int = 0`，旧 state/save 缺字段时默认 0；
- [ ] `_RoundCtx` 读取并跨交互式单 action 调用保留该计数；
- [ ] 成功主动解锁后原子地扣款、加入 `unlocked_mechs`、计数 +1；
- [ ] 第二次主动解锁返回稳定错误码 `UNLOCK_LIMIT_REACHED`，资金、集合、计数均不变；
- [ ] `advance_round` 将计数重置为 0；双方玩家互不影响；
- [ ] `env.legal_actions()` 在额度为 0 时不再枚举新的 `UNLOCK_UNIT` 候选；

| D1 | 单兵种、正向、120s 维修剑齿虎 | 首发、攻击数、弹数、actual damage |
| D2 | 同 D1，90°/180° 朝向 | 转向时间、首发延迟、120s 损失 |
| D3 | 靶在射程内左右切换 | 转向、换靶、周期保持 |
| D4 | 钢球/熔点击杀靶 | TTK、截断伤害、击杀前事件 |
| D5 | 犀牛/沙虫近距边界 | 实际射程、接触、反杀隔离 |
| D6 | 骇客 lv1–9 | 120s 转化阈值和进度曲线 |

### 6.3 科技

| Case | Control / treatment | 必测指标 |
|---|---|---|
| K1 | 猎犬 / 猎犬+燃烧弹 | 火区半径、持续、tick、单体/群体伤害 |
| K2 | 鬼鳐 / 鬼鳐+全弹发射 | 2→10、cycle×2.5、弹分配、120s DPS |
| K3 | 鬼鳐 / 鬼鳐+高爆 | impact 受害者数、半径、衰减 |
| K4 | 狂蝎 / 狂蝎+双发 | 两发时序、同靶、实际 DPS |
| K5 | 台风 / 台风+残骸引爆 | 首杀前输出、爆炸、连锁、归属 |

### 6.4 解锁合法性

| Case | 操作 | 预期 |
|---|---|---|
| U1 | 同一玩家同回合连续主动解锁 A、B | A 成功，B 被禁用/拒绝且不扣款 |
| U2 | 下一回合主动解锁 B | 额度恢复，B 成功 |
| U3 | 持剑齿虎/台风等兵种专家进入部署 | 对应 mech 在 oracle 冻结时点自动解锁 |
| U4 | 领取单位获得卡 | 获得单位且对应 mech 自动解锁 |
| U5 | 领取单兵种强化增援 | oracle 确认是否自动解锁，并冻结 ID/kind 范围 |
| U6 | 持巨型专家/空军专家 | 不批量自动解锁整类；只保留其原费用/属性规则 |
| U7 | 先自动解锁 A，再主动解锁 B | B 仍可成功，说明自动解锁不占额度 |
| U8 | 主动解锁后 Undo，再解锁另一单位 | Undo 恢复额度；最终仅一个主动解锁 |
| U9 | 0 元主动解锁 | 成功并消耗本回合额度 |
| U10 | 双方各主动解锁 1 个 | 两方独立，均成功 |

## 7. 测试与 Gate

### 7.1 数据/对齐 Gate

- [ ] 两份 `.grbr` hash、游戏 build、转换命令入 manifest；
- [ ] 10 pair 全部有解析状态，2 个空场明确 skipped，8 个有效 fight 有唯一 case id；
- [ ] deploy/fight/report round 不靠位置猜测；
- [ ] 所有待测单位可回连 source/member/card；
- [ ] mixed case 无逐 source 归因时自动拒绝生成 per-unit 数值；
- [ ] 原始 oracle 数据只读，派生产物写新目录。

### 7.2 几何/动力学 Gate

- [ ] 爬虫坐标不进入大型目标 footprint；
- [ ] 任意两活爬虫不出现持续性大面积重叠；
- [ ] 单方向 96+ 爬虫可绕至背面，不全部堵在正面轴线上；
- [ ] 内圈开火数与 oracle 容差一致；
- [ ] 射程内不无故换靶，射程外存在更近目标时能换靶；
- [ ] 目标死亡后群体能重新流动，不形成永久冻结环；
- [ ] 相同 seed 双跑轨迹/事件 digest 相同；
- [ ] 1500 爬虫 120s 性能不超过当前基准的 2 倍，若超过必须提交 profile 和优化说明。

### 7.3 伤害/转向 Gate

- [ ] 单发伤害、弹数、攻击周期、首发时刻分别断言；
- [ ] 120 秒 actual damage 有绝对误差和相对误差，不能只报 ratio；
- [ ] 建议稳态兵种相对误差 `<=5%`，复杂随机/清杂兵种 `<=10%`；超出需逐事件解释；
- [ ] 重炮 0°/90°/180° 的首发时间误差建议 `<=0.2s` 或一个 oracle tick；
- [ ] 击杀靶场景用 TTK 与截断曲线，不把 120 秒伤害截顶值当准确；
- [ ] 伤害修正不破坏装备护盾/吸血/维修的 receipt 口径；
- [ ] 不允许用 `atk_mul` 单一旋钮同时掩盖转向与武器周期错误。

### 7.4 科技 Gate

- [ ] 猎犬燃烧弹和火神火区有独立 spec；
- [ ] 鬼鳐全弹发射明确验证 10 枚与总 cycle 2.5×；
- [ ] 鬼鳐高爆与台风残骸引爆在正确的爬虫密度模型上标定；
- [ ] 狂蝎双发的两次伤害通过同一 ledger 且不重复整轮伤害；
- [ ] 每项科技单独关掉时只改变相关 case；
- [ ] 未采集到的字段保持 provisional/unsupported。

### 7.5 解锁 Gate

- [ ] 每方每回合主动解锁上限为 1，下一回合 reset；
- [ ] 第二次主动解锁拒绝时 state/supply/ledger digest 不变；
- [ ] 已解锁、失败、Undo 的动作不错误消耗最终额度；
- [ ] 0 元主动解锁仍消耗额度；
- [ ] 六个明确兵种专家的对应 mech 自动解锁，时序与 oracle 一致；
- [ ] 类别专家不会误解锁其 `unitIds` 全集；
- [ ] 单位获得卡自动解锁 grant mech；单位专属强化卡按 oracle 冻结表执行；
- [ ] 自动解锁不占手动额度，重复来源幂等；
- [ ] legal action、执行器、save/load、advance_round 使用同一计数语义；
- [ ] 回放中所有 folded plan 的多 `UnlockUnit` 情况均有解释，无静默放行第二次；
- [ ] 核心完成后已向 RL 方交付 mask 同步说明，未同步时报告 stale blocker。

### 7.6 回归 Gate

- [ ] 本轮 feature 全关：八库仍为 1793/2349，逐 case digest 不变；
- [ ] 本轮 feature 全关：human baseline 仍为 4124/7122；
- [ ] 装备 runtime 12/12 微型场景与 19 项专项测试不回归；
- [ ] 新 oracle 库逐 case 报 winner、alive、end time、damage、attack count、trajectory；
- [ ] 与本轮机制无关的 human pair 逐 case outcome digest 不变；
- [ ] 所有非 RL 测试通过；RL 仅允许预期的 engine version stale，不改其代码；
- [ ] 正式 A/B 报 good/bad/net flips、survivor 变化、end-time 变化和 paired bootstrap CI。

## 11. Definition of Done

只有同时满足以下条件才可结项：

- [ ] 两份新 `.grbr` 全部完成可审计对齐，8 个有效 fight 无身份歧义；
- [ ] Oracle manifest 包含游戏/工具/数据 hash，所有正式数值均有 source；
- [ ] 爬虫不能穿透大型单位，不能大规模重叠，能形成内外圈并绕至空闲侧；
- [ ] 剑齿虎周围活动/攻击爬虫数与 oracle 达到冻结容差；
- [ ] 射程内保持与射程外换靶均通过受控实验；
- [ ] P0 高估兵种完成单体输出与转向拆解，不以总倍率硬拟合；
- [ ] P1 低估兵种至少完成磁暴、骇客、泰山的机制复核；
- [ ] 猎犬燃烧弹、鬼鳐全弹/高爆、狂蝎双发、台风残骸引爆均有独立 oracle A/B；
- [ ] 骇客 120 秒最低成功等级与相邻失败等级已冻结；
- [ ] 钢球/熔点/Rhino/Sandworm 的特殊靶场边界均有报告；
- [ ] 每方每回合主动解锁最多 1 个，失败/Undo/0 元和跨回合 reset 边界均通过；
- [ ] 兵种专家与已确认特定增援自动解锁对应 mech，且不占主动额度；
- [ ] 类别专家和无关增援没有产生批量误解锁；
- [ ] 新 oracle 动力学、DPS、清杂库全部通过；
- [ ] OFF 臂 1793/2349 与 4124/7122 bit-exact；
- [ ] ON 臂不相关 pair 零变化，相关 flips 可回连；

- [ ] 装备 runtime 回归通过，装备 oracle 未决项仍如实列出；
- [ ] transition schema/save adapter 已验证，RL mask 同步状态已明确移交；
- [ ] 只在最后 bump engine version，并通知 RL/Transformer 重建正式 sim labels。
