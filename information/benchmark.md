# Benchmark：八库定义与当前一致率

> 怎么跑：见 `benchmarks/README.md`（`python benchmarks/run.py --lib all`）。
> 本文档讲库的来历、语义与现状。

## 一致率是什么

每个基准库的每场对局都有两份结果：

1. **oracle 真值**（`winner_oracle`）：活体游戏内模拟器（Windows 注入管线）
   跑出的胜负 / 逐单位伤害 / 击杀，存于 `data/exp/<lib>/`
2. **pysim 重算**：本仓库引擎在出厂默认 opts、固定种子下重算

两者胜负一致的比例即一致率，是模拟器保真度的核心指标。
**当前合计 1793/2349 ≈ 76.3%**（step29.1 定版口径）。

## 场景的公共结构

```jsonc
{
  "name": "u001", "group": "U",        // U=兵种对位 B=建筑 CAL=标定 SPC/TECH=专项
  "pair": [22, 25],                     // 主对位兵种 id（建筑为负 id）
  "value": [820, 820],                  // 双方等经济总价（卡价+科技价+建筑价）
  "p0": {"units": [...], "techs": {"22": [链折叠后的科技id]}},
  "p1": {...},
  "constructions": {"0": [], "1": [{"cid":1,"x":..,"y":..}]},
  "towers": {"0": [0,0], "1": [0,0]},   // 塔强化等级
  "desc": "U 台风(22) vs 鬼鳐(25) 等经济820"
}
```

- 布局：p0 一队在左塔外侧 20-30m、p1 镜像右塔外侧，相向推进；
  残局打塔是特性（覆盖攻塔 DPS / 塔瘫痪）
- 建筑局（group B/CAL/BP）对拍时统一 `bld_term=2`（机动单位全灭即终局）

## 真值（data/exp/）里有什么

每场一个 json：内嵌场景 + oracle 遥测（逐 (team,uid) 的 dmgReal/dmgMax/kills）
+ `winner_oracle` + 刷新用的 pysim 臂（`arms.factory`，即当前引擎重算结果，
与 `benchmarks/run.py` 的重算同构）。

## 现状解读（76.3% 意味着什么）

- s27（无科技对照）88.6% 说明**裸机制**（走位/索敌/弹道/伤害）已相当可信
- 拉低总分的主要是 s26（官方阵容，科技叠加复杂）与 s29cal（维修类机制标定）
- 差异可视化：`http://127.0.0.1:8300/bench` 逐场回放对拍（每库徽标显示
  当前一致率），或 `benchmarks/run.py --regen-exp` 导出重算记录做离线 diff
- 未烘焙 opts 与机制修正候选项见 `information/engine-opts.md`
