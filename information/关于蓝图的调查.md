# 蓝图 ID 与回放字段调查结论

## 结论

回放中的 `PAD_ActiveBlueprint` 和 `playerData/bluepints` 确实对应蓝图/研究中心购买状态，但两者含义不同：

- `actions[].type == "ActiveBlueprint"`：本回合尝试激活的蓝图动作，ID 在动作的 `ID` 字段中。
- `playerData/bluepints`：回合开始时的状态快照。成功激活后通常在下一条回合快照中出现；研究中心升级时，旧等级会被新等级替换。
- 临时效果是否在本回合生效，应看本回合 action，不能只看 `bluepints`。

调查数据：`local_data/humen_rounds.json`，1106 局完整回放，使用每个玩家自己的连续 `rounds` 快照核对，而不是只用带标签的 `pairs`。

## `ActiveBlueprint` ID 对照

回放协议没有保存蓝图名称，因此 1/2/3 的名称不能仅凭 `bluepints` 字段作数学上的直接证明；下面的三项是结合 UI 顺序、出现时机和购买动作做出的高置信映射。4/5/401/501 则有 `officers` 状态变化作为直接证据。

| 回放 ID | 对应效果 | 证据 |
|---:|---|---|
| 1 | 快速补给（高置信推断） | 属于 1/2/3 的指令中心临时蓝图组；常在已有购买动作之后使用 |
| 2 | 批量征召（高置信推断） | 属于 1/2/3 的指令中心临时蓝图组；全量最常见，通常在购买单位前使用 |
| 3 | 精英征召（高置信推断） | 属于 1/2/3 的指令中心临时蓝图组；作用于本回合单位购买等级 |
| 4 | 进攻强化 | 下一回合出现研究专家 `20310`；`bluepints` 出现 `4` |
| 5 | 防御强化 | 下一回合出现研究专家 `20300`；`bluepints` 出现 `5` |
| 401 | 进攻强化 II | 下一回合出现研究专家 `20311`；`bluepints` 中 `4` 被 `401` 替换 |
| 501 | 防御强化 II | 下一回合出现研究专家 `20301`；`bluepints` 中 `5` 被 `501` 替换 |

因此，研究中心的 ID 对照是确定的：

```text
4   -> 进攻强化   -> officer 20310
5   -> 防御强化   -> officer 20300
401 -> 进攻强化II -> officer 20311
501 -> 防御强化II -> officer 20301
```

`bluepints` 中可以看到的研究状态通常是四选二的形式：`4/401` 选其一、`5/501` 选其一；II 级出现后会移除对应 I 级 ID。这说明它是长期研究状态，而不是“本回合是否刚刚点击”的日志。

## 强化瞄准和高速移动的字段

这两个效果在回放中不是 `ActiveBlueprint`：

| action 类型 | 字段 | 效果 | 生命周期 |
|---|---|---|---|
| `ActiveEnergyTowerSkill` | `SkillID=5` | 强化瞄准：远程单位射程 `+15` | 当前回合 |
| `ActiveEnergyTowerSkill` | `SkillID=6` | 高速移动：全体单位速度 `+3` | 当前回合 |

它们虽然在游戏界面上可能和指挥中心效果一起被理解，但在回放协议里属于能量塔技能通道。当前回合是否使用，要读取本回合 `actions`；下一回合不应从 `bluepints` 推导这两个 buff。

## 对 transition 的使用建议

状态应拆成两类：

1. 长期状态：直接读取回合开始快照中的 `bluepints`，研究中心效果还应读取对应的 `officers` ID。
2. 本回合动作状态：扫描本回合 `ActiveBlueprint` 和 `ActiveEnergyTowerSkill`，处理快速补给、购买数量/等级以及射程/速度临时 buff。

所以不能只把 `bluepints` 当成“本回合已生效 buff 列表”。正确边界是：

```text
playerData(round i) + actions(round i)
    -> round i 的购买与临时效果
    -> playerData(round i+1) 的累计状态快照
```

当前仓库的回放转换器已经保留了这两类信息：`blueprints` 来自 `bluepints`，原始动作保存在 `actions`。
