# 强化学习路线图（Mechabellum / 钢铁指挥官）

> 本文档是整个项目的最终目的：把战场模拟器作为廉价环境，贯彻强化学习。
> 模拟器本体见根 README；本文只讲建模。

## 1. 把游戏规范成 MDP

这是一个典型的自走棋游戏。先把它规范成一个完整的 RL 问题（MDP/MDP-R）。

### 观测 o

双方场面的整体观测 o 完整描述了双方一回合开始对战前的所有状态：

- **全局状态**：专家（开局选择的专家 + 后续增援卡牌拿到的专家）、各个兵种
  解锁了哪些科技、经济（剩余钱数）、研究中心等级（1 级 / 2 级攻击加强或
  血量加强）、技能 CD（如核弹还有几回合可用，0 表示本回合可用）、当前回合数
- **每个兵的状态**：兵种、朝向、位置、等级、经验值、回收价格
- **技能**：哪些位置被布置了战场技能（路径、飞弹的释放位置）
- **双方血量**与血量上限
- （可能还有没列到的）

o 的三个分量：

```
o = ( f0, f1, cards )
```

- `f0` / `f1`：我方 / 对方玩家的专家与战场
- `cards`：下一回合的 4 个候选卡牌 / 单位概念

### f 的不唯一性与序列化

我们打算用序列来描述 f。f 的信息前后交换（比如交换两个单位出现的前后）
有时场地不变，即同一战场对应多个序列。希望模拟器和学习框架尽可能对 f 序列
**消歧**：一个战场只对应一个序列（尽可能即可）。

模拟器可以负责建立一套类似 XML 的语言（与回放同构）描述一个战场，并且这个
战场描述可以直接传递进模拟器。

### 动作集合 A

部署阶段玩家会进行一连串动作（不考虑撤销）：

```
a_1, a_2, ..., a_T
```

- 已解析出共约 **14 种**不同的 a（带 id 和属性，如"购买特定 id 的兵"、
  "移动兵到 x,y"）
- 动作是异构的：购买一队新兵会产生一个 id（场地上新增一队位置可移动的单位，
  即 f 发生了改变）。合理做法：action 模型在执行购买后额外输出自己推理出的
  这队兵的 id（`购买 xx 兵种 as id xx`），这样后续移动优先指 action 序列中
  购买的单位
- **支援卡牌（增援选择）作为 a 的 mask**

### 增援卡牌与增援单位

- 增援卡牌用序列描述：`<choiceA> card_A_infos <choiceB> ... <choiceE> {弃选金额}`
- action 阶段第一件事就是在 A–E 中选择
- 增援单位是增援卡牌的特殊情况：说明每张增援是什么单位、几级、几只
- **开局也可以看成 4 选 1**（`<choiceA> 专家id + 200元兵种A 1级2个 + 100元兵种B 1级3个 ... <choiceD>`，此时无 choiceE），
  于是第 1 回合也是一个增援选择

### 转移函数 T

```
o' = T( o, {a}_1, {a}_2 )
```

- 双方都进行了各自的动作序列后，战场进入新状态
- transition 函数过滤掉不合法的操作：`T( f0, cards, A0 ) -> f0'`
- 需要根据 buff 把回合金增加上
- **从 o 到 o' 的路径不唯一**（动作顺序不敏感）
- transition（外围经济模拟）在 pysim 中尚未实现，是最重要的下一步开发

### Reward

单回合 reward 简写为「胜利方对失败方扣血百分比」的单调函数：

- 玩家 0 单回合 reward = `damage_to_1 / max_hp_1 − damage_to_0 / max_hp_0`
  （对对方扣血百分比；双方可能都有兵残留，两项可以都非零）
- 把对方血量扣到 ≤0：额外 **+100%**；自己被扣到 ≤0：额外 **−100%**
- 平局存在；至少一方血量 ≤0 时模拟结束
- 战斗会轻微影响 f：battle 之后（无论 simulate 还是 real）双方单位**涨经验**，
  经验影响 action 侧能否给特定单位升级

## 2. 战场模拟器的作用

```
battle_simulate( f_0 , f_1 ) --> battle_result
```

battle_result 最重要的信息：

- 双方各自有什么单位存活 / 对对方的扣血（**Reward 计算的关键**）
- 每个单位对对方的输出、增加了多少经验

除 pysim 外还有真实战场（`battle_real`，Windows 注入 API、更珍贵）；
训练在 Linux，通过远程排队提交战局、要回真实结果。battle_real 不一定有
逐单位输出（那是 oracle 模拟才有的，即 benchmark 数据）。

**pysim 的好处：cheap，强化学习的各种搜索都可以慢慢跑起来。**

## 3. 建模策略

- **V(o) 最重要**：先建模单回合的胜利与否。V 是很简单的 O→实数映射，
  本质是定 reward
- **π(o)**：生成 {a} 序列，模仿玩家操作行为（历史数据 pretrain）

强化学习之前：V 已能较准确判断局势；π 已能像玩家一样采样出策略。

### 单回合强化学习设想

1. 从历史采样一个局面 o
2. 用当前 π 为双方生成 N 组策略候选（我方 A_1..A_N，对方 B_1..B_N）
3. 计算 `V_ij = V( T(o, A_i, B_j) )` —— 典型的"石头剪刀布"零和博弈，
   可解双方最优混合策略
4. 假设对方用最优混合策略，得到我方每个策略的最终得分，反馈给 π
5. 在最优混合策略下采样一组真实对局交给模拟器排队（加入 V 的训练集）

（单回合有可能短视）目标拟合带贴现的 `Ṽ`（tiled V），可由 scale 对齐的
V 初始化。

### 多回合学习策略

1. 从历史某前三回合采样局面 o
2. 用 π 和 V 生成完整双方对局
3. 根据每回合 `Ṽ_ij` 更新 π
4. 用 V 计算每回合累计收益，更新 `Ṽ`
5. 每回合交给模拟器 query，数据更新 V

模拟器完备后应直接上多回合学习策略。

### 一个理想的 inference 回合

```
sample 历史对局 -> 每回合 cards（第 0 回合双方 cards 候选不同）
o0 = {,,cards0} -> AC(o0) -> A0 （开局双方选择，互相可见）
o  = {f0,f1,-}  -> A0 <- AC({f0,f1,-}) （购买 1-2 个新单位 + 全单位布局）
f0 <- Transition(f0, -, A0)；f1 同理
battle_result = battle_simulate(f0, f1)
按 battle_result 更新 f（涨经验）、结算扣血
后续回合：A <- AC({f, f_opp, cards}) -> Transition -> battle -> 循环
```

### 累计 Reward

```
累计收益 = 当回合 reward + β·下回合 reward + β²·下下回合 reward + ...
```

这个累积收益就是 V 函数的拟合目标。

## 4. 平衡模拟器与真实的差异

V 函数给 **2 个头**：

- 一个回归 **pysim 引擎**下的累积收益
- 一个回归**真实**的累积收益

pysim 训练收敛后再慢慢累积真实对局；另有约 1000 局真实 benchmark 约束。

## 5. 序列化建议（0821 对幻想口袋的回复）

- 想利用局面的 Markov 性，可把数据转成 `O0 <o2a> A1 <a2o> O1 <o2a> A2 ...`
- 战场描述序列**唯一描述**观测，并尽可能在顺序上消歧
- A 中是否包含对手动作：可以先我方后对方；学习时甚至只学我方
  （敌方动作实际作为观测）
- O 和 A 尽量多用 **share token**（兵种、技能统一）
- 该模型同时学习 AC 和 transition（真跑 RL 时 A→O 是已知确定过程）
- 关于打分：每步挑最容易做高的候选、其余落点只能通过向赢家塌缩的
  softmax 权重拿梯度的问题——空间上什么都没学到，是建模要注意的点
