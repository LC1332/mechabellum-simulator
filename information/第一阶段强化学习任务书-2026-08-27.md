## 0. 阶段定位与结论

本阶段命名为 **RL Phase 1**，但核心是“RL 前的监督基线 + 第一个策略改进闭环”，不是
PPO、自博弈或完整多回合强化学习。

本阶段只做五件事：

1. 冻结模型实际消费的最小 observation/action/data contract；
2. 从真实回放建立无泄漏、高置信、可追溯的数据集；
3. 训练 `V_battle_sim`，预测 pysim 单场战斗结果；
4. 使用同一局面编码器增加独立的 `V_battle_real` 头，拟合真实回放 FightReport；
5. 训练逐原子动作的 `pi_BC`，让它能生成完整、可执行的部署计划，并在冻结局面集上进行
   `pi_BC vs replay/random/heuristic/pi_BC` 初步对战以及 best-of-N 尝试。

第一阶段的核心证明不是“模型 token accuracy 很高”，而是：

```text
真实回放 -> 可审计数据 -> pi_BC 逐 prefix 生成合法 plan
                           |
                           v
                    transition 执行双方 plan
                           |
                           v
             direct pysim battle + V_sim/V_real 诊断
                           |
                           v
              固定对手池评估 / best-of-N 改进
```

完成本阶段后，可以决定是否进入“单回合候选博弈与离线策略改进”。本阶段不因为模型能在
pysim 内获胜，就声称其已能迁移到真实游戏。

## 1. 范围、成功标准与非目标

### 1.1 必做范围

- `BattleObservationV1`：部署完成、开战前的双方公开战场；
- `PolicyObservationV1`：某一方部署阶段的 ego-centric 公开观测；
- `PolicyActionV1`：逐原子动作建模，每次动作后由 transition 更新 shadow state；
- `battle_real_v1`、`battle_sim_v1`、`policy_prefix_real_v1` 三类数据集；
- 简单非神经 baseline；
- 一个小型、置换不变的 battle encoder 和 sim/real 两个明确分开的输出头；
- 一个小型 prefix policy `pi_BC`；
- 固定数据切分、统一 metrics、静态诊断报告和错误样例浏览；
- 单回合初步对战、side swap、共同随机种子和 best-of-N direct-sim 评测。

### 1.2 第一阶段成功分三层判定

| 层级 | 判定条件 | 含义 |
|---|---|---|
| 工程完成 | 数据可追溯、模型可复现、mask rollout 零拒绝、arena 可跑 | RL/模型基础设施成立 |
| 模型有效 | Value 和 BC 均显著优于相应简单 baseline | 模型确实学到可泛化信号 |
| 策略改进证明 | `pi_BC + best-of-N direct pysim` 在冻结对手池上稳定优于原始 `pi_BC` | simulator 已能推动单回合策略改进 |

三层必须分开报告。若工程完成但 best-of-N 没有提升，应记录为“Phase 1 工程完成，策略改进
gate 未通过”，不能通过换测试集或只展示成功样例来掩盖。

### 1.3 非目标

- 不做 PPO、SAC、MCTS 长程 rollout 或多回合 policy-gradient；
- 不训练 `V_episode`，不把 `V_battle` 冒充长期价值；
- 不要求从完整 Normal 1v1 开局独立生成所有 opening/reinforcement offer；
- 不要求 `pi_BC` 第一版学习开局/增援四选一；这些选择默认由回放或 arena fixture 外生注入；
- 不让模型预测 legality、transition、永久 entity ID 或资金变化来替代规则系统；
- 不用 `V_battle_sim` 代替便宜的 pysim 作为最终 arena 裁判；
- 不把 provisional/approximate 的战斗机制混入 gold real 指标后再宣称真实域提升；
- 不提交原始 `.grbr`、大型训练 shard 或 checkpoint 到 git。

## 3. 第一阶段冻结的建模语义

### 3.1 `V_battle` 的准确含义

`V_battle_*` 的输入是 **双方部署都已结束、battle 尚未运行**的战场。它不负责预测下一回合
经济，也不隐含未来 policy。

两个域分别为：

```text
V_battle_sim(s_prebattle)  -> pysim 的 W/D/L 概率与期望扣血
V_battle_real(s_prebattle) -> 真实游戏的 W/D/L 概率与期望扣血
```

以 ego side 为 0 时，统一标签：

```text
y_wdl             in {loss, draw, win}
y_damage_to_opp   = damage_to_player[1] / max_hp_player[1]
y_damage_to_self  = damage_to_player[0] / max_hp_player[0]
y_damage_diff     = y_damage_to_opp - y_damage_to_self
```

模型必须输出完整的 `p_loss/p_draw/p_win` 与双方 damage 分量。可为排序导出一个标量：

```text
v_rank = E[y_damage_diff] + lambda_terminal * (p_win - p_loss)
```

但 `lambda_terminal` 和公式必须绑定 `value_target_version`；数据中不只保存这个 scalar。

### 3.2 sim/real 双头口径

推荐第一版使用一个共享 `BattleEncoder` 和两个独立 domain head：

```text
BattleEncoder
  ├─ SimHead  -> WDL + damage_to_opp + damage_to_self
  └─ RealHead -> WDL + damage_to_opp + damage_to_self
```

约束如下：

- sim 标签只更新 `SimHead`；real 标签只更新 `RealHead`；
- 共享 encoder 是否对 real 有帮助，必须与“完全独立 real 模型”做 ablation；
- 不能把 sim/real 标签混成一个无 domain 标识的 target；
- 对同一 replay pre-battle state 尽量同时产生 real 标签和多 seed sim 标签，形成 paired set；
- 单独输出 `sim_real_disagreement`，它是诊断量，不是伪造的真实 reward；
- 若共享训练使 `V_real` held-out 指标变差，第一版发布两个独立 checkpoint，而不是强行共享。

### 3.3 `pi_BC` 的准确含义

第一版不直接生成一整个自由文本 plan，而是生成下一个原子动作：

```text
pi_BC(a_t | o_t, legal_mask_t)
o_{t+1} = transition_shadow(o_t, a_t)
```

循环直到 `END_DEPLOY`。这样购买后产生的新单位会在下一次 observation 中获得新的
observation-local handle，模型无需创造永久 ID 或跨整段维护 `new_ref`。

训练时使用 teacher forcing：从真实 pre-deploy state 开始，逐条执行 canonical human action，
每个成功 prefix 产生一个 `(PolicyObservationV1, legal mask, target atomic action)` 样本。推理时
使用完全相同的 transition 和 mask 路径。

双方计划必须从同一个 root state 的两个独立 shadow env 生成；生成某一方计划时，不得因为
代码执行顺序看到另一方本回合尚未公开的最终 plan。

### 3.4 Phase 1 action profile

建立版本化 `rl_phase1_core_v1`，默认包含：

- `END_DEPLOY`；
- `UNLOCK_UNIT`、`BUY_UNIT`、`UPGRADE_UNIT`、`BUY_TECH`、`MOVE_UNIT`；
- 已经 transition-complete 的 `SELL_UNIT`；
- Step 4 已完成 typed contract 且 gold 数据足够的能量塔技能；
- 已完成、目标形状可被 observation-local handle、单个坐标明确表达的指挥官技能和装备。
  多落点、直线、路径和 multi-unit 技能在专门参数 head 完成前不进入 core profile。

opening/reinforcement 选择先由 fixture/回放外生应用，再让 `pi_BC_deploy` 接管部署动作。未进入
profile 的 round 对 BC 必须整轮排除或截断到第一个 blocker，不能先偷偷执行人类未知动作再
继续生成后续训练标签。

## 4. 模型 Observation 与动作参数契约

### 4.1 `BattleObservationV1`

至少包含：

- round、双方当前/max HP；
- 双方 tower strengthen、officer、blueprint、当回合 tower mods；
- 双方全部持久单位：mech、level、exp bucket、位置、朝向、装备、已购科技；
- 本场已释放且会影响 battle 的技能、装置、区域和召唤事件；
- battle fidelity/confidence flags；
- schema/ruleset/engine/observation version 只作为 metadata，不默认作为可学习特征。

禁止包含：

- FightReport、winner、damage、战后经验、下一回合 HP；
- battle seed 的未来结果信息；
- replay 文件名、玩家名、game index、label path；
- 永久 `entity_id` 的数值大小；
- 真实游戏中不可见且会造成作弊的内部 RNG/牌池状态。

### 4.2 `PolicyObservationV1`

在 `BattleObservationV1` 可复用字段上增加：

- 当前 supply、购买额度 quote、可解锁单位、tech 前置；
- 本回合单位移动 permission/reasons；
- 技能/装备库存、费用、CD、目标类型；
- 当前 prefix 长度、剩余 action budget；
- 每个己方单位的 observation-local handle；
- 当前 legal verb/target mask 的版本与摘要。

对手经济、未公开选择和内部 cooldown 等字段只有确认在真实游戏可见时才能加入。第一版
默认采用最小公开集；不确定字段放在 metadata/diagnostic，不输入模型。

### 4.3 Ego-centric 与对称性

- 任意 side 都映射成“我方在统一半场”的 ego 视角；
- player 1 的 y、朝向、tower/skill position 按同一函数镜像；
- set/map 排序稳定，单位内部顺序不进入 pooled battle encoder；
- side swap 后，`p_win`/`p_loss` 和双方 damage 输出应互换；
- 镜像、side swap 和单位 permutation 必须有属性测试。

### 4.4 Handle

- handle 只在一次 `PolicyObservationV1` 内有效；
- handle 必须唯一、连续、可逆地解析到当前 entity；
- 下一次 observation 允许因 canonical sort 重新编号；
- 模型输入和输出都不能出现 `entity_id`、`replay_index`；
- observation 给出的每个 handle 经 action 执行必须 100% 指向同一个单位；
- 数据中保留内部 entity 映射只能用于审计，训练 loader 必须显式丢弃。

### 4.5 `pi_BC` 参数头

第一版使用分层 head，避免大型通用 tokenizer：

```text
verb head
  -> unit pointer / mech candidate / tech candidate / skill candidate
  -> bounded x,y distribution（只对 buy/move/position skill）
  -> orientation / END
```

- verb 和离散目标使用 transition 生成的 mask；
- unit target 使用 pointer score，不分类永久 ID；
- x/y 使用 ego 坐标归一化到 `[-1, 1]`，通过有界分布或 squashing 保证不越界；
- 若规则存在真实离散部署格，优先使用规则格点；否则使用连续坐标头，不把当前
  `legal_action_candidates()` 的 10×10 探针当成真实动作空间；
- 参数 head 只在对应 verb 下计算 loss；
- `END_DEPLOY` 必须是模型动作，不能仅靠达到最大长度强制结束；
- 最大 64 个原子动作作为安全阀，触发时记录 `forced_end/action_budget`。

## 5. 数据工程任务

### 5.1 数据产物

建立三个 source-of-truth 数据集：

| 数据集 | 输入 | 标签 | 用途 |
|---|---|---|---|
| `battle_real_v1` | 真实 pre-battle state | FightReport WDL/damage | `V_battle_real` |
| `battle_sim_v1` | 同构 pre-battle state + 固定 seed 集 | pysim WDL/damage | `V_battle_sim` |
| `policy_prefix_real_v1` | 每个人类合法 prefix 后的 policy obs/mask | 下一原子 action | `pi_BC` |

审计真源使用 sharded `jsonl.gz` + manifest；tensor/feature cache 只是可删除的派生产物。每条
样本至少带：

```text
sample_id, replay_hash, match_id_hash, round, ego_side
game_version, schema/ruleset/engine/observation/action/data_version
source_tier, fidelity, confidence, exclusion_flags
observation_digest, action/prefix_digest, battle_input_digest
split, augmentation_parent_id, seed(s)
```

### 5.2 Gold / Silver / Excluded 分层

`battle_real_v1`：

- Gold：双方最终 pre-battle board 可恢复；FightReport 完整；battle effect 无 unsupported；
- Silver：可直接从 replay `units_fight` 重建 battle board，但外围 transition 有残差，或含
  provisional/approximate 机制；
- Excluded：标签缺失、当前动作会改变 battle 但无法表达、引用歧义、字段泄漏或版本未知。

`policy_prefix_real_v1`：

- Gold：整轮 canonical plan 在 phase1 profile 内，每个 teacher-forced prefix 均 accepted；
- Silver：只在第一个 blocker 前形成诊断 prefix，不进入主训练；
- Excluded：Undo 未正规化、目标引用不明、target 不在 mask、transition 状态不可信。

主指标只使用 Gold。Silver 只能用于覆盖/误差研究，必须单独报表。

### 5.3 真实标签恢复

- 真实 battle label 优先来自同一回合的两个 FightReport；
- damage 使用已有已验证关系，不从赢家名称猜测；
- draw 保留为独立类别，不能删除后把任务伪装成更高准确率的二分类；
- `units_fight`、canonical transition 后 board 和 FightReport participant 必须做三方对齐；
- 对齐失败保存首个 diff：缺失/多余 unit、level、tech、equipment、skill effect；
- 当前约 1106 局、8228 个真实标签回合、7122 个 sim 对齐回合只是旧审计参考值，Step 4
  同步后以新 manifest 为准。

### 5.4 sim 标签生成

- `battle_sim_v1` 至少包含两种 `state_source`：真实 human pre-battle board，以及只从 train
  root 生成的 counterfactual board；
- 第一轮 counterfactual 可由 random legal、heuristic、human plan 局部扰动产生；`pi_BC`
  可用后再增加其 sampled candidates，并升级 dataset/label version；
- counterfactual 的全部候选继承 root replay-group split，validation/test root 绝不进入训练；
- 同一 root 下保存 `candidate_group_id`，Value ranking 指标只能在同组候选间计算；
- 所有 counterfactual plan 必须 prefix-legal、receipt 全 accepted，并保存 plan/state digest；
- split 必须先按 replay state 冻结，再生成 sim seed；
- seed 由 `sha256(sample_id + seed_index + sim_label_version)` 稳定派生；
- train 默认每个 battle state 4–8 个 seed；validation/test 默认 16–32 个 seed，用于更稳定地
  估计期望和 aleatoric variance；
- 原始每 seed outcome 和按 state 聚合后的分布都保存；
- 记录 battle runtime、end_time、单位数、事件数和 fidelity warning；
- seed 数允许根据吞吐报告调整，但调整必须生成新的 `sim_label_version`；
- 相同 battle input + seed 的 outcome digest 必须 exact。

### 5.5 去重与无泄漏切分

本地回放目录存在同名 `(2)` 等潜在重复文件，必须在 split 前去重：

1. 原始文件 hash 完全相同的只保留一个 source；
2. 原始 hash 不同但 canonical match/round digest 相同的建立 duplicate group；
3. duplicate group 只能整体进入一个 split；
4. 同一 replay 的双方视角、各回合、seed 扩增和 side-swap 扩增必须在同一 split；
5. 数据增强在 split 之后执行。

主切分按比赛时间/游戏版本做 train/validation/test，并报告玩家重叠。另建立一个
player-held-out stress split；若玩家对局图形成巨大连通分量导致无法完全 player-disjoint，
必须报告原因和实际重叠率，不能假装无泄漏。

模型选择只看 validation。test 在配置冻结后统一运行，并保留首次正式 test 结果。

### 5.6 最低数据止损线

以下不是质量目标，而是决定是否值得训练神经模型的最低线：

- battle Gold train 少于 1000 个独立 state：只交付数据/树模型，不发布神经 Value 结论；
- policy Gold 少于 5000 个独立 prefix：只做频率/候选 ranking baseline；
- 任一关键 action kind 的 train 样本少于 100：合并为不支持或仅做诊断，不报告该类准确率；
- validation/test 某桶少于 30 个 replay-group：只展示样本数和宽置信区间，不做强结论。

## 7. T2：`V_battle_sim` 与 `V_battle_real`

### 7.1 第一版模型

推荐一个小型 DeepSets 风格模型，控制在约 1–5M 参数：

- unit MLP：mech/tech/equipment embedding + level/exp/position/orientation；
- 双方分别做 sum/mean/max pooling；
- global MLP：round、HP、tower、skill/event 摘要；
- 对双方使用共享 unit encoder；
- advantage 路径尽量采用 `g(self, opp) - g(opp, self)` 保证 swap 反对称；
- damage 路径对 attacker/defender 复用同一函数；
- 输出 SimHead 与 RealHead 的 WDL logits、damage 均值和可选方差。

第一版不要求大型 Transformer。若 DeepSets 明显无法表达近邻/区域技能，可在 ablation 中增加
轻量 pairwise attention，但不得替换掉简单 baseline 后只报告复杂模型。

### 7.2 Loss 与校准

```text
L_domain = CE(WDL)
         + lambda_damage * Huber(damage_to_opp, damage_to_self)
         + lambda_symmetry * consistency(side_swap)
```

- loss 权重写入 config；
- sim 多 seed state 可使用软 WDL 分布和平均 damage；
- real 单次观测保留 sample uncertainty，不伪装成确定期望；
- class imbalance 用 sample weight 或 balanced sampler，并报告未加权真实分布指标；
- temperature scaling/isotonic 等校准器只在 validation 拟合；
- checkpoint 同时保存未校准与校准后结果。

### 7.3 Value 必报指标

- WDL：NLL、Brier、accuracy、balanced accuracy、confusion matrix；
- calibration：ECE、reliability diagram、confidence histogram；
- damage：MAE、Huber/RMSE、bias、分位数误差；
- ranking：同一 root/candidate group 的 pairwise ranking accuracy 和 Spearman；
- symmetry：side swap 概率/伤害不一致；
- domain：SimHead、RealHead、sim-real disagreement 分开报告；
- 分桶：round、game version、单位数、总价值、兵种、科技、装备、tower/skill、fidelity；
- 稳定性：至少 3 个训练 seed 的均值/标准差；
- 性能：dataset samples/s、train step/s、CPU/GPU inference/s、峰值内存。

### 7.4 Value 错误样例

报告至少保存：

- 最自信但判断错误的 real/sim 各 50 个 state；
- damage 绝对误差最大的各 50 个；
- SimHead 与 RealHead 分歧最大的 100 个 paired state；
- side swap 不一致最大的样例；
- 每个样例的模型输入摘要、真实/模拟结果、fidelity warnings 和可回放命令；
- 按兵种/科技/技能聚合的 residual，帮助判断是模型问题还是 pysim fidelity 问题。

### T2 Gate

- test WDL NLL/Brier 优于 constant prior；
- damage MAE 优于 mean-by-round baseline，目标至少相对下降 10%；
- `V_sim` 候选 ranking accuracy 目标不低于 0.65，且优于树模型；
- 校准后 ECE 目标不高于 0.10；
- side swap consistency 在数值容差内通过；
- `V_real` 必须独立报告；若未超过树模型，保留为实验头而非“已完成真实 Value”；
- test 指标附按 replay-group bootstrap 的 95% CI，不能把相邻 round 当独立样本计算 CI。

## 8. T3：`pi_BC` 前缀行为克隆

### 8.1 训练样本生成

对每个 Gold human plan：

1. 建立真实 pre-deploy root state；
2. 外生处理本阶段不学习的 opening/reinforcement 选择；
3. 生成 `PolicyObservationV1` 和 mask；
4. 检查 human target 在 mask 内；
5. 写入一个 prefix sample；
6. 在 shadow env 原子执行 target，检查 receipt accepted 和 digest；
7. 继续直到 human `END_DEPLOY`；
8. 保存最终 human board、supply、battle input，供 plan-level 评价。

任一 prefix 失败时保留 first-failure diagnostic；主训练不能跳过失败动作后继续使用未来标签。

### 8.2 模型与解码

- 复用或复制经过验证的 unit/global encoder，不强制与 Value 共享权重；
- verb head 使用 masked cross entropy；
- unit/mech/tech/skill 使用候选集合上的 pointer/ranking loss；
- 坐标使用 bounded likelihood，并额外报告 L1/L2 与落点热力图；
- orientation 使用条件 Bernoulli；
- 默认提供 greedy、temperature、top-p 三种解码；
- 同一 root 可用不同 sampling seed 生成多样 plan；
- masked mode 禁止无候选动作；debug tolerant mode 只能用于测量未约束输出，不参与 arena；
- 检测重复 no-op、A-B-A state cycle、超长 plan，并给出明确 stop reason。

### 8.3 Teacher-forced 指标

- verb top-1/top-3 accuracy、macro F1、每类 precision/recall；
- target pointer top-1/top-k、candidate count 分桶；
- 坐标 MAE、方向准确率、按 move/buy/skill 分开；
- `END_DEPLOY` precision/recall、计划剩余长度下的停止校准；
- target-in-mask recall、mask size、模型非法 raw probability mass；
- per-action NLL 和整 plan NLL；
- 按 round、版本、单位数、plan length、action kind 分桶。

### 8.4 Free-running / 执行级指标

必须从 root state 自由生成完整 plan，再交 transition 执行：

- 语法有效率、semantic rejection rate、receipt reason 分布；
- 正常 `END_DEPLOY` 比例、forced-end 比例、action 数分布；
- 最终 supply 差、购买数差、科技/升级集合差；
- board edit distance：单位 multiset、level、tech、位置最优匹配距离、朝向；
- 与 human plan 的 battle regret：固定 opponent plan 和共同 battle seeds 下直接 pysim 比较；
- action diversity：不同 seed 的 unique plan digest、verb entropy、位置覆盖；
- no-op/repeated action/cycle 比率；
- 从 root 到最终 state 的全 receipts 与 first divergence drill-down。

### T3 Gate

- masked free-running plan 的 action rejection 为 0；
- 正常 END 比例至少 99%，forced-end 小于 1%；
- verb/target 指标显著优于条件高频 baseline；
- plan-level board/supply 指标优于 END-only 和 random-legal；
- side 0/1 镜像后的指标差异处于 bootstrap CI 内；
- 3 个训练 seed 结果稳定，无只靠单 seed 的偶然 checkpoint；
- checkpoint 绑定 contract、split、feature、model config 和代码 commit digest。

## 9. T4：初步对战与 best-of-N

### 9.1 Arena 的局面与公平性

冻结一个 `arena_phase1_v1`：

- 只从 test/arena 专用 replay-group 取 root state；
- 模型选择过程中不可查看 arena label；
- 每个 matchup 做 ego side swap；
- 使用共同 battle seed 比较两个策略，降低 simulator 随机方差；
- 同一 root 上双方 plan 从独立 shadow env 生成；
- 直接 pysim 是最终裁判，`V_sim` 只用于预筛/诊断；
- 真实回放标签和 `V_real` 只用于 sim-to-real warning，不用于挑 test 最优 checkpoint。

### 9.2 必跑策略池

```text
END-only
random legal
simple heuristic
human replay plan（可视为数据参考，不是公平在线 policy）
pi_BC greedy
pi_BC sampled
pi_BC + best-of-8 direct pysim
pi_BC + V_sim prefilter(32 -> 8) + direct pysim top-k
```

必跑 matchup：

1. `pi_BC` vs random legal；
2. `pi_BC` vs simple heuristic；
3. `pi_BC` vs frozen human replay opponent plan；
4. `pi_BC` vs `pi_BC`，用于检查对称性、side bias 和生成稳定性；
5. best-of-N 与原始 `pi_BC` 在同一 opponent/root/seed 上做 paired improvement。

初步对战以单回合为强制交付。若同步后的 env 已通过 seed、snapshot、prefix mask 和 1000 局
soak gate，可额外做 2–4 回合 `sandbox_v1` chained exhibition；其结果单列为实验，不阻塞 Phase 1。

### 9.3 候选选择

最小版本先固定对手 plan：

```text
our K plans = pi_BC.sample(root, K)
score each plan against frozen opponent plan with common seeds
choose direct-sim best plan
```

第二版再为双方各生成候选并形成 `K x M` payoff matrix。若做混合策略，求解器、正则和数值
误差必须单测；本阶段不以零和求解器为必做项。

`V_sim` prefilter 必须保留 direct-sim 复核。记录 Value top-k recall：真正 direct-sim 最优候选
有多少被 Value 预筛保留。

### 9.4 Arena 指标

- win/draw/loss、平均/中位 damage diff、尾部 10% 表现；
- paired improvement 及按 replay-group bootstrap 95% CI；
- side swap bias、seed variance；
- action rejection、forced END、plan length、supply spend、单位/科技多样性；
- 每局 policy latency、Value latency、battle latency、候选总成本；
- best-of-N 曲线：N=1/2/4/8/16；
- Value prefilter top-k recall 和相对 direct-sim 的 regret；
- 按 round、版本、单位规模、机制/fidelity、对手类型分桶；
- “高收益异常”清单：重叠布阵、极端边界坐标、重复技能、异常经济、超长计划等 exploit 信号。

### T4 Gate

- 所有 matchup 计划 100% 可执行，无 silent ignore；
- `pi_BC vs pi_BC` side-swap 后没有显著固定 side 偏置；
- `pi_BC` 至少优于 END-only/random 中一个非学习 baseline；
- `best-of-8 direct pysim` 相对同 checkpoint 原始 sampled `pi_BC` 的 paired mean reward 改善
  95% CI 下界大于 0，才算通过“策略改进证明”；
- `V_sim prefilter` 若不能保留至少 90% 的 direct-sim top-1，则暂不用于正式候选搜索；
- 所有 top exploit 样例经过人工/trace 审计并进入 regression fixture 或明确标记 unresolved。

## 10. 诊断系统与报告格式

用户需要比单一 loss/胜率更多的诊断。本阶段每次正式 run 都生成：

```text
  configs/
  data_report.json
  split_report.json
  metrics.json
  metrics_by_bucket.jsonl

```

其中 `run_manifest.json` 至少记录 git dirty 状态、commit、命令、环境依赖、CUDA/CPU、所有

`report.html` 为静态离线报告，至少支持：

- 总览 Value/BC/Arena gate；
- train/val/test 与 Gold/Silver 覆盖；
- confusion/calibration/damage residual；
- action confusion、END 校准、坐标热力图；

- sim-real disagreement；

日志只保存 hash 化玩家/比赛 ID，默认报告不展示真实玩家名。任何聚合百分比必须同时展示
分子/分母，空桶不能画成 0%。

### 10.1 必做健康检查

- label shuffle；
- tiny-set overfit；
- train/test duplicate detector；
- observation leakage scanner；
- unit permutation invariance；
- ego mirror/side swap consistency；
- 相同 checkpoint/input 的 inference digest；
- 相同 battle input/seed 的 outcome digest；
- NaN/Inf、梯度范数、参数范数、class entropy、dead head；
- 各 loss 的未加权数值，防止一个 head 被权重掩盖；
- config/chosen checkpoint/test report 的引用闭环。

### 12.1 Contract / 数据

## 13. 实施顺序、时间盒与里程碑

按单人主开发估算约 3–5 个开发周；若并行，仍必须按 gate 合并，不能让模型分支自建一套
observation/action 语义。

### R0：同步审计与 Contract（2–4 天）

完成 Step 4 审计、phase1 profile、Battle/Policy Observation、handle/mirror/mask golden tests。

### R1：数据与 Baseline（3–5 天）

完成去重切分、三类数据集、覆盖报告、非神经 Value/policy baseline。

### R2：双域 Battle Value（3–5 天）

先在人类局面与 random/heuristic 反事实候选上单独训练 SimHead/RealHead，再做共享 encoder；
交付完整 calibration/error report。

### R3：Prefix `pi_BC`（5–8 天）

先 teacher-forced heads，再 free-running plan；优先解决 rejection、END 和执行差异，不先堆模型。
随后只在 train root 采样 `pi_BC` 候选，生成一次版本化的 V_sim 分布扩展；是否重训 Value 由
validation ranking 指标决定。

### R4：Arena 与 best-of-N（3–5 天）

冻结 checkpoint/局面/对手池，完成 paired direct-sim 评测、Value prefilter 和 exploit 审计。

### R5：结项（1–2 天）

重跑正式 test/arena、生成报告、补 model/data card、记录未通过 gate 和 Phase 2 建议。

## 15. 进入下一阶段的 Go / No-Go

只有以下条件同时成立才建议进入“单回合候选博弈、rejection sampling/DAGGER 式离线策略
改进”：

1. `pi_BC` masked rollout 零拒绝且能稳定结束；
2. `V_sim` 在未见 root/candidate 上有可靠排序能力；
3. `V_real` 至少能作为独立的方向性诊断，sim-real 分歧不是纯噪声；
4. best-of-N direct-sim 对原始 BC 有统计显著改善；
5. 改善不是来自已知 simulator exploit；
6. arena 结果对 side、seed、round、单位规模和对手池不过度敏感。

若 1 不通过，回到 contract/mask；若 2 不通过，候选少时继续直接 sim，不阻塞 BC；若 3
不通过，扩大/清理真实数据，不得用 SimHead 冒充；若 4–5 不通过，优先查候选多样性、Value
排序和 simulator fidelity，不进入多回合 self-play。

## 16. 默认裁决与待复核项

以下默认值用于避免实施停摆，实际数据审计若给出反证，应升级 contract 版本：

1. `pi_BC` 第一版只学习 deployment，opening/reinforcement 由外部先执行；
2. opponent 本回合 plan 不作为当前 policy 输入；双方从相同 root 独立生成；
3. 坐标先使用连续有界 head，除非同步后的规则层已经提供权威离散格；
4. Gold Value 排除 approximate/provisional battle effects，Silver 单独研究；
5. RealHead 主要来自历史回放，不在本阶段接 Windows `battle_real` 在线 query；
6. arena 的强制结论来自单回合 direct pysim；短链多回合仅作 exhibition；
7. 第一版优先小模型、强 baseline 和完整诊断，不以参数规模作为里程碑。
